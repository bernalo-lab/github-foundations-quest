# GitHub Foundations Quest

## Learn GitHub by investigating

Welcome to **GitHub Foundations Quest** — a practical introduction to GitHub for QA professionals and aspiring Incident Engineers.

This is not a traditional GitHub tutorial.

You won't spend hours watching someone explain repositories, commits, pull requests and CI pipelines.

Instead, you have been given an incident to investigate.

The evidence is somewhere inside this repository.

Your job is to find it.

---

## Your Mission

A small online application has started generating **duplicate payment requests** for some customers.

The problem appeared recently.

The engineering team suspects instability at an external payment provider.

They may be right.

They may be wrong.

You have been asked to investigate.

During the investigation you will use the repository itself as evidence.

You will learn how to:

- navigate an unfamiliar GitHub repository;
- search files and configuration;
- examine commit history;
- compare changes using diffs;
- follow Issues and Pull Requests;
- interpret review comments;
- inspect CI/CD evidence;
- use GitHub Copilot to assist an investigation;
- distinguish an AI-generated explanation from verified evidence.

You do not need previous professional GitHub experience.

You **do** need curiosity.

---

## How the Quest Works

The Quest is divided into levels.

Each level gives you an investigation objective.

Completing that objective introduces another GitHub capability.

### Mandatory Investigation Levels

**Level 0 — Enter the Scene**  
Access the repository and orient yourself.

**Level 1 — Find the Evidence**  
Navigate and search the repository for information relevant to the incident.

**Level 2 — Reconstruct the Change**  
Use Git history to determine what changed, when and why.

**Level 3 — Follow the Engineering Trail**  
Connect Issues, Pull Requests, review comments and CI evidence.

### Additional Levels

**Level 4 — Make the Fix**  
Create a branch, make a change, commit it and open a Pull Request.

**Level 5 — Challenge the AI**  
Use GitHub Copilot to assist your investigation — then verify what it tells you.

Levels 0–3 form the GitHub foundation required for the QA → Incident Engineering course.

Level 4 introduces contribution skills and may be required by later exercises.

Level 5 is an optional stretch challenge.

---

## The Investigation Rule

Throughout this Quest, remember one rule:

> **An explanation is not evidence.**

That applies whether the explanation comes from:

- another engineer;
- an Issue;
- a Pull Request;
- a commit message;
- documentation;
- GitHub Copilot;
- or your own first hypothesis.

Find the evidence.

Then decide what you believe.

---

## Before You Begin

Do not try to understand every file in the repository.

Real Incident Engineers rarely begin an investigation with complete knowledge of the system.

Start with the reported symptom.

Follow the evidence.

Change your hypothesis when the evidence requires it.
